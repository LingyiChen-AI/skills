# 工作流细则

## 1. 理解需求

### 判断企划类型

| 类型 | 典型说法 | 大纲模板 |
|---|---|---|
| 活动企划 | 发布会、年会、快闪、展会、路演、促销活动、品牌活动 | `outlines.md` → 活动企划 |
| 营销 / 推广方案 | 营销方案、推广方案、campaign、品牌传播、内容营销、618/双11 | → 营销方案 |
| 产品 / 新品上市企划 | 新品上市、产品规划、GTM、上市方案 | → 产品上市 |
| 通用企划 | 说不清类型，或是项目立项、内部改进方案 | → 通用企划 |
| 超充站 / 充电站 | 超充站、充电站建站、可研、补贴申报、场地合作、开站活动、充电运营 | `industry/supercharging.md`（行业包，优先于上面几类） |

混合需求（比如「新品上市发布会」）以一个类型为主，从另一个类型借章节。

### 必须有的信息

| 信息 | 缺了怎么办 |
|---|---|
| 主体（品牌 / 产品 / 公司是谁） | **必须问**，这个没法假设 |
| 目的（为什么做） | 按类型套常见目的，写进「假设」 |
| 时间 | 按「1—2 个月后执行」假设 |
| 预算 | 给一个与规模匹配的预算，标注为「建议预算」 |
| 规模 / 地点 / 人群 | 按行业常识假设 |

**提问规则**：只有主体不清楚时才先问，而且**一次问完，最多 3 个问题**。其他缺失信息一律带假设往下写，
把所有假设集中列在文末「附录：假设与待确认事项」里。用户在飞书里只发了一句话，就是希望直接拿到稿子。

### 用户给了资料

用户发的品牌资料、往期方案、数据表都要读完，事实以资料为准。资料里有的数字不要自己编；
资料没有、但方案需要的数字（预算拆分、KPI）可以估算，并在正文或附录里标明「估算」。

## 2. 定大纲

从 `outlines.md` 取模板，**按需删减或合并**：小活动不需要竞品分析，内部方案不需要传播计划。
正文章节 6—10 个为宜（附录不算），单章不超过 4 个二级标题。模板章节超过 10 个时，按 `outlines.md` 每个模板下面的「合并建议」处理。

## 3. 写正文

- 新建工作目录，正文写到 `proposal.md`，图片放 `images/`（统计图由脚本放 `charts/`）。
- frontmatter 必填 `title`、`subtitle`、`client`、`author`、`date`；`theme` 主色按品牌色或行业挑
  （见 `visuals.md` 的主色建议）。
- 第一章一律是「项目概述」：一个「一句话方案」提示框（时间、地点、做什么、核心目标数字）加一张关键信息表。
  老板只看这一页也能明白要做什么。

## 4. 配图规划

见 `visuals.md`。每章至少要有一样视觉元素（统计图、配图、表格、提示框都算），整份企划书至少 3 张图。
统计图（```chart）由脚本画，不用生图。

## 5. 生图

**用你自己的生图能力画图，不需要任何 API key。**操作步骤见 `visuals.md`「生图操作」。要点：
- 先 `build.py proposal.md --list-images` 拿到清单，`todo` 是还没画的张数。
- 逐张提交生图，**等每个任务出结果**（千问办公里会先显示「已提交生图任务」，要等图片生成出来）。
- 用 `images.py save` 把结果存到清单里的 `save_to` 路径。
- 全部存完再跑一次 `--list-images`，`todo` 为 0 才进入下一步。

## 6. 排版出稿

```
python <skill_dir>/scripts/build.py proposal.md                # docx + pdf
python <skill_dir>/scripts/build.py proposal.md --format pdf   # 只要 pdf
```

脚本最后打印一段 JSON：`outputs` 是生成的文件，`images` 是用到的全部配图（含封面），
`placeholders` 是还没画、临时用了占位图的配图，`warnings` 是需要处理的问题。

- `placeholders` 不为空：回到第 5 步把这几张补画、存好，再重跑 build。占位图放在 `_placeholders/`，**不占用正式路径**，
  补好图后重跑就会自动换成真图。实在画不出来，交付时告诉用户哪几张是占位图。
- `warnings` 里提示「PDF 没生成」（环境里没有 LibreOffice）：交付 docx，并说明原因；
  如果你的环境自带「Word 转 PDF」功能，可以用它把 docx 转成 PDF。

## 7. 自检

```
python <skill_dir>/scripts/preview.py 输出文件.pdf --pages 1,3
```

查看 `_preview/contact.png` 总览图，`--pages` 指定的页另存为高清单页（`--pages` 用 PDF 页序；
封面和目录占前两页，所以页脚页码 = PDF 页序 − 2，脚本输出里两个都会写）。脚本会报出：
- **空白页**：一般是手动写了 `<!-- pagebreak -->`，删掉即可。
- **孤页**（正文不到 1/4 页）：上一页的结尾被挤了过来。处理办法：把前面的图调窄（```chart 加 `"width": 13`，
  图片写成 `![图注|13](路径)`），或精简文字，或把提示框挪到图前面。

然后看图检查：图表文字有没有重叠或截断、配图是否切题、有没有乱码文字。再按 `qa-checklist.md` 检查内容。

## 8. 交付

- 发 PDF 给用户；用户要改稿的话，再附上 Word。
- 消息正文写三五行：方案一句话、核心数字（预算 / 目标）、需要用户确认的假设（最多 3 条）。
- 用户提修改意见时：改 `proposal.md` 后重新 build，不要直接改 docx。
