# 设计需求单流程

用户是品牌 / 运营人员，要把一个物料需求交给设计方（外包设计公司或内部设计）。
目标：**一份需求单发过去，设计师不用回来追问，第一稿就接近定稿。**
真实情况是一个宣传页改了 6 轮、新站效果图改了 3 轮，大部分返工是需求单没写清楚（见 `types.md` 各类「常见返工点」）。

## 1. 理解需求

1. 读品牌档案 `brands/<brand>/brand.md`（不写 `brand` 就用 `brands/DEFAULT` 里的目录）。品牌名、logo、色值、定位语、广告语、地址、站点信息都从这里取，
   **不要自己改写**。
2. 判断物料类型 → `types.md` 对应一节。一次需求含多种物料（如「效果图 + 导视」）就写在同一张单里，分区块写。
3. 对照该类型的「必须拿到」清单，看用户给了什么。

**提问规则**：只在**物料是什么、给谁用**都不清楚时才问，一次问完，最多 3 个问题。
字体、二维码、电话、版式选哪个这类问题**不要问**，写成【待补】或在需求单里并列「方案 A / 方案 B」，同一轮出 Word 和 PDF。其他缺的信息一律写 `【待补：xxx】` 往下写，
文末「需提供的素材」表里汇总。用户在飞书里只发一句话，就是希望直接拿到可以转给设计的需求单。

## 2. 写文案

- 用户给了文案：**原样保留**，只做错别字和标点修正；可以按 `types.md` 的结构重新排顺序，并补设计说明。
  卖点文案用户写了「可优化」才改写，改写后保持数字不变。
- 用户没给文案：按类型结构写。要求：
  - 受众是重卡司机和车队：**短、直白、数字放前面**，「每台每年省 4000—6000 元」好过「全面降本增效」。
  - 标题一屏能读完：主标题每行不超过 12 个字，户外广告标题不超过 10 个字。
  - 行动号召用对仗短句：「三重大礼 · 限时放送 │ 名额有限 · 先到先得」。
  - 每个卖点只突出一个关键词或数字（`**加粗**`）。
  - 不写套话：「赋能」「全方位」「打造」「引领」「极致」。
- 数字（价格、权益、桩数、尺寸）只能来自用户或品牌档案，没有就写 `【待补】`，**不能编**。

## 3. 写设计说明

每个区块想一遍：设计师拿到这段文案，会不会问「做多大、放哪、什么颜色、配什么图」？会问就写一条 `>` 说明。
- 版式：卡片 / 并排 / 几列几行 / 整体放大
- 颜色：每个区域用什么底色、渐变方向，不能用什么颜色
- 配图：`> [!配图]` 逐项写清图的类型和底色
- 去掉的东西：明确写「不要 / 去掉」
- 交付：源文件 + JPG（默认），要上会的写「看稿先出」

## 4. 出稿

```
python <skill_dir>/scripts/brief.py brief.md             # docx + pdf
python <skill_dir>/scripts/brief.py brief.md --format docx
```

素材（logo、产品图、现场照片）放 `brief.md` 同目录的 `images/`，品牌 logo 直接写 `brand:logo.png`。
输出 JSON：
- `warnings`：品牌规则检查（旧广告语、宣传页写了电话号码、缺「最终解释权」声明）、缺图、PDF 没生成。**有就改完重出**。
- `todos`：文中所有【待补】，交付时列给用户。
- 没有 LibreOffice 时只出 docx，照常交付。

## 5. 自检

`python <skill_dir>/scripts/preview.py <输出.pdf> --pages 1,2` 看页面，再过一遍 `qa.md`。

## 6. 交付

- **只发 Word（设计师要能直接复制文案）和 PDF**，就是 `brief.py` 输出里 `outputs` 的两个文件。
  `brief.md`、json、规则文件不发给用户。
- 消息写三五行：做的是什么物料、尺寸、`todos` 里的待补项（让用户补齐后再转设计）。
- 用户提修改或补信息：改 `brief.md` 重出 Word 和 PDF，不要直接改 docx，也不要只回一段文字。
- 用户给的新规则（「电话留空手填」「海报都加脚注」）写进本次需求单，**不改品牌档案、不另出规则文件**。
- 改稿意见：按 `types.md` §6 的格式出 Word 和 PDF，消息里再附一段同样内容的文字，方便用户直接贴群。
