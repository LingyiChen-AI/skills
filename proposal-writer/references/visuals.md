# 配图规划与生图提示词

## 先列清单再动笔

正文写完后，逐章填一张表（不用写进文档，自己心里过一遍即可）：

| 章节 | 这一章最需要让人「看见」什么 | 视觉元素 | 来源 |
|---|---|---|---|
| 项目概述 | 一眼看懂 | 提示框 + 信息表 | 文字 |
| 背景 | 趋势 / 差距 | 折线图 / 条形图 | ```chart |
| 核心创意 | 现场长什么样 | 空间概念图 | ```image |
| 排期 | 时间线 | 甘特图 | ```chart |
| 预算 | 钱的去向 | 环形图 + 表 | ```chart + 表格 |

规则：
- 数据一律用 ```chart，**不要用生图来画图表**：生成的数字和文字不可靠。
- 架构、流程、关系类内容，优先用表格或列表表达；确实需要示意图时，用生图画「简洁扁平信息图」，并且图里**不放文字**。
- 生图只用于：封面主视觉、空间 / 舞美 / 展位概念、主视觉海报方向、产品使用场景、氛围参考。
- 整份企划书生图 2—5 张就够，多了会显得空。封面图建议必配。

## 图片分四类，诚实标注

| 类别 | 用途 | 能不能生成 | 图注写法 |
|---|---|---|---|
| 证据类 | 往期活动实拍、真实产品、真实数据 | **不能**，只能用用户提供的 | 「2025 年成都站现场」 |
| 概念类 | 舞台、空间、展位、动线效果 | 可以 | 「……概念示意（效果图，非实景）」 |
| 氛围类 | 调性、情绪、色彩方向 | 可以 | 「视觉氛围参考」 |
| 结构类 | 分区、流程、关系 | 优先用表格 / 图表；要画就画无文字的扁平示意 | 「……示意」 |

不要用生成的人群、舞台或产品图冒充「已经办过 / 已经验证」的证据。

## 提示词怎么写

按下面的顺序写成一段中文，控制在 200 字以内：

1. **主体与动作**：画面里是什么、在做什么
2. **场景与空间**：在哪里、尺度、前中后景
3. **构图与机位**：视角（人眼平视 / 俯视 45° / 正面），主体占比，**需要叠加标题的话写「左侧留白」**
4. **光线与材质**：自然光 / 暖光，具体材质（拉丝金属、哑光、木纹）
5. **色彩**：主色、辅助色，最好和 frontmatter 的 `theme` 呼应
6. **风格**：商业摄影 / 建筑可视化渲染 / 扁平插画 / 产品棚拍
7. **结尾固定加「无文字」**：生图里的中文经常是乱码，标题和文字都由文档负责排版

示例（空间概念）：
> 商场中庭里的室内微型徒步步道概念效果图，步道依次经过碎石路、木栈道、仿真溪流和一个小型观景台，两侧有低矮绿植和岩石造型，几位年轻人穿着轻户外服装行走，俯视 45 度视角，墨绿与米白配色，柔和自然光，建筑可视化渲染风格，无文字

示例（封面主视觉）：
> 城市商场中庭里的户外主题快闪空间，前景是岩石造型展台和几件冲锋衣，背景是印着山脊线条的浅色幕墙，天窗自然光，墨绿、米白为主色，干净高级的商业摄影风格，画面左侧留白，无文字

反向提示词默认已包含：乱码文字、错别字、随机 LOGO、水印、扭曲手指、多余肢体、低清晰度。要额外排除的元素写进 `negative`。

## 比例

- 通栏横图 `16:9`（默认）；封面 `16:9` 或 `4:3`
- 海报、竖版物料 `3:4`，插入时加 `"width": 10`
- 方形 `1:1`（产品单品），插入时加 `"width": 11`

## 主色建议（frontmatter theme）

有品牌色就用品牌色（取较深的那个）。没有的话按行业选：

| 行业 / 调性 | 主色 |
|---|---|
| 户外、自然、健康 | `#1F6F5C` 墨绿 |
| 科技、互联网、B2B | `#1F5FBF` 科技蓝 |
| 美妆、时尚、女性 | `#B23A6B` 玫红 |
| 餐饮、零售、促销 | `#C8452B` 番茄红 |
| 咖啡、茶饮、烘焙 | `#6B4226` 咖啡棕 |
| 节日（春节、中秋） | `#A3262A` 中国红 |
| 高端、金融、地产 | `#2B3A55` 藏青 |
| 新能源、充电、储能 | `#0E7C66` 电能绿 |
| 母婴、教育、亲子 | `#E08A1E` 暖橙 |

表里没有的行业，按调性找最接近的一行。主色要够深，白字放在它上面要看得清（表头是白字压主色）。不要用浅黄、浅绿。
统计图的第一个颜色也会用主色。

## 生图操作

图片**由你自己的生图能力生成**（千问办公里是「生图任务」），脚本不调用任何生图接口，也不需要 API key。

1. **拿清单**：
   ```
   python <skill_dir>/scripts/build.py proposal.md --list-images
   ```
   返回每张图的 `prompt`、`ratio`、`caption`、`save_to`（要存到的完整路径）和 `done`（是否已存在），封面图也在里面。

2. **逐张生图**：把 `prompt` 原样交给生图能力，比例按 `ratio` 设置（16:9 横图、3:4 竖图……）。
   生图是异步任务：提交后会先显示「已提交生图任务」，**要等图片真正生成出来再处理下一步**，不要提交完就去排版。
   可以几张一起提交，再统一等结果。

3. **存到指定路径**：生图结果给的是图片链接，或者工作区里的文件路径，都用下面这条命令存：
   ```
   python <skill_dir>/scripts/images.py save "<图片链接或文件路径>" "<save_to>"
   ```
   脚本会下载或复制图片，转成 PNG，过大的自动缩小。

4. **核对**：再跑一次 `--list-images`，`todo` 为 0 就可以 build 了。

5. **挑图**：生成的图有乱码文字、畸形肢体，或者和提示词明显不符，就改提示词重画，覆盖原文件。

画不出来（生图失败、额度用完）时：build 会自动放灰色占位图（图上写着图注和提示词），
输出里的 `placeholders` 会列出这些图，交付时要告诉用户哪几张需要补图。
