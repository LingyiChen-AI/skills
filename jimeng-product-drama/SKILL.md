# 即梦产品讲解短剧（真人出镜，约 1 分钟）

把一条产品视频 + 2 张人物照片，做成「冲突 → 产品解决 → 结果」的 1 分钟竖屏剧情片。
基于 OnlyShot（MIT，原文件在 `upstream/`）精简：去掉市场扫描、多集大纲、ref 库和分镜图层，
改成 **5 段 × 10～12 秒长镜头，用真人照片直接做全能参考**。

所有脚本在 `scripts/`，用 `python scripts/<名>.py` 调用，参数第一个是项目目录。

## 实测事实（2026-11-13，以此为准，`references/` 里冲突的说法作废）

| 事项 | 结论 |
|---|---|
| 真人照片做参考 | **可以**。multimodal2video 传真人照片能出片、脸很稳。OnlyShot 文档「即梦 2026-02-09 停用真人主体参考」不成立 |
| 模型 | 默认 `seedance2.0fast_vip`：约 6 积分/秒，12 秒段 72 积分，3～5 分钟出片。`seedance2.0fast` 约 4 积分/秒但标准会员排队约 10 小时，别用 |
| 单段时长 | Seedance 2.0 系列 4～15 秒；一段 prompt 里写 2～3 个分镜头，模型会自己切镜 |
| 并发 | 5 段同时提交没问题，全部约 5 分钟 |
| 音频 | 自带中文对白和环境声，口型基本能对上；对白是否念对要人听 |
| 网页端任务 | CLI `list_task` 看不到网页端提交的任务，反之网页「全能参考」历史能看到 CLI 任务 |
| 片头留白 | prompt 写「留出空白区域」会生成一整条纯白画面，不要写 |

## 流程

### 0. 前置检查
```bash
dreamina version || ls ~/bin/dreamina.exe     # 没装：curl -fsSL https://jimeng.jianying.com/cli | bash（Windows 用 Git Bash）
dreamina user_credit                          # 未登录：dreamina login --headless，把 verification_uri 给用户去浏览器授权，
                                              # 同时后台跑 dreamina login checklogin --device_code=<code> --poll=600
```
余额要 ≥ 秒数 × 6 × 1.5（留重拍余量）。

### 1. 看素材
```bash
python scripts/看视频.py <产品视频> <项目>/素材检查      # 每 6 秒一帧、带时间戳的联系表
```
用 Read 逐张看联系表和人物照片。记下：每个卖点出现的原片时间、画面字幕原文、人物外形（发型、服装、配饰）。

### 2. 写 `<项目>/01_故事与痛点分析.md`
复制 `templates/01_故事与痛点分析.md` 填写。章节顺序固定为：**故事 → 人物 → 痛点分析 → 场景解决对照 → 出片说明 → 附录（原片拆解）**。
原片时间轴放附录、标题注明「不是本片时间轴」，否则用户会以为故事没改。

故事配方（约 60 秒）：

| 段 | 时长 | 内容 |
|---|---|---|
| 1 | 12s | 冲突开场：痛点爆发（积压 / 出错亏钱），配角发难，主角接下挑战 |
| 2 | 12s | 产品登场：配角质疑 → 主角操作 → 产品自动干活（讲 2～3 个卖点） |
| 3 | 12s | 打消顾虑：配角问「会不会出错」→ 产品的安全机制 |
| 4 | 12s | 结果 + 算账：第二天数据、成本 |
| 5 | 10s | 收尾：人被解放，品牌露出 |

每段最多讲 2～3 个卖点；原片卖点放不下的，在文档里写明删了哪些。写完给用户确认再出片。

### 3. 写 `<项目>/分镜.json`
复制 `templates/分镜.json`。每段 prompt 的结构固定为：

1. 第一句：`@图片1 作为<主角>的形象参考，@图片2 作为<配角>的脸部形象参考。`（顺序与 `refs` 一致）
2. 第二句：服装锚点，**每段原样复制同一句**（不写会每段换发型 / 首饰）
3. `镜头1（0-4秒）：…` `镜头2（…）：…` `镜头3（…）：…`，对白用中文引号、每句 20 字内
4. 公共 `style` 自动追加：写实、竖屏、脸与参考图一致、**画面中不要出现任何文字、字幕和品牌标识**

措辞替换（实测）：
- 「黑眼圈很重」→「面容疲惫，只有淡淡的黑眼圈（不是淤青）」
- 「表情变坚定」→「表情笃定，嘴角带一点自信的笑，不惊讶、不张大嘴」
- 杯子 / 手机等道具 → 加「无品牌标识的」
- 产品界面 → 只写「蓝白色调的软件界面自动运行」，真实界面后期叠

可选 `subtitles: [[开始秒, 结束秒, "文字"], …]`（段内相对时间），拼初剪时自动烧字幕。

### 4. 出片：先 1 段，再其余
```bash
python scripts/出片.py <项目> all --dry-run        # 看字数和预估积分
python scripts/出片.py <项目> 1                     # 后台跑（run_in_background），约 3～5 分钟
python scripts/抽帧检查.py <项目> 1                 # Read <项目>/检查/段01.jpg
python scripts/出片.py <项目> 2 3 4 5               # 第 1 段脸和风格 OK 再出其余
python scripts/抽帧检查.py <项目>
python scripts/出片.py <项目> 3 --redo              # 某段不满意：改 prompt 后重出
```
验收每段看：两人脸是否像参考图、服装锚点是否一致、分镜头顺序是否对、有无品牌 / 文字 / 白屏、表情是否符合剧情。

### 5. 拼初剪
```bash
python scripts/拼初剪.py <项目>     # → 初剪.mp4（720x1280，原声，右上角「AI生成」，有 subtitles 就烧字幕）
```
抽一帧 Read 确认角标位置，再把结果、积分花费、逐段问题清单报给用户。

### 6. 后期清单（交给用户或继续用 ffmpeg 做）
- 电脑 / 手机屏幕叠产品真实界面截图（从产品视频截）
- 卖点大字、片尾 logo + slogan（从产品视频最后一帧截）
- 发布前过 `references/compliance-2026.md`：AI 标识、肖像授权（出镜的真人要本人同意）

## 常见错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 照搬 OnlyShot 36 镜 × 4～10 秒 | 产品片 3 分钟、积分翻倍 | 5 段 × 10～12 秒 |
| 用默认 `seedance2.0fast` | 排队 10 小时 | `seedance2.0fast_vip` |
| 以为真人照片会被拦，先去生成 AI 形象 | 白花积分、脸不像 | 直接用真人照片做参考 |
| 5 段一次全提交 | 风格不对时 5 段全废（约 350 积分） | 先出第 1 段验收 |
| 在 bash 里拼中文 prompt 调 dreamina | 引号转义坏、任务被静默丢弃 | 只用 `scripts/出片.py`（参数列表调用） |
| 多段下载到同一目录再按时间改名 | 段号对错视频 | 每段独立临时目录（脚本已处理） |
| 让 AI 画产品界面 | 界面字是乱码 | 后期叠真实截图 |
| 「不要字幕」只写在末尾公共 style 里 | 对白多的段被模型烧进字幕，还有错别字（实测出现过不雅错字） | 每段 prompt **第一行**写「画面纯净：绝对不要出现任何字幕、文字、标题或水印，对白只用声音和口型表现。」 |
| 把只在部分段出场的角色 / 特效写进公共 style | 不该出现的段也出现（觉醒前就有金瞳和精灵） | 公共 style 只放全片通用的画风；特效角色写进出场的段；关键的「没有特效」段明确写「眼睛正常、没有 XX」 |
| 多角色片全片共用一组 refs | 参考图超 9 张或不出场的人被画进来 | 每段写自己的 `refs`，只放该段出场角色（脚本已支持） |
| 配角定妆照用四宫格全身 | 小脸容易变形 | 用单人半身或膝上 3/4 身正面照（`--ratio=3:4`），全身信息靠文字描述 |
